# Generated PESCO artifacts and reports

The report directories are reproducible visualization snapshots produced by
`python -m PESCO.visualization`; the A–F experiment artifacts below are
generated by their dedicated benchmark/training runners, not by the visualization
module:

* `demo_report/` uses deterministic fabricated policy records to smoke-test
  every plot and CSV path. It is **not** scientific evidence.
* `tier0_report/` executes the repository's deterministic Tier-0 simulator and
  trusted verifier (64 MVP branches). It is a pilot diagnostic, not a trained
  model result or a claim of autonomous discovery.
* `pesco_pilot/` contains the end-to-end CPU reference loop. Its
  `mvp_counts.json` records the 16 same-state branch groups, 64 exploration-seed
  observations, and the matched single-seed audit reruns; `baseline_manifest.json`
  records adapter/reference boundaries and `formal_comparison_eligible=false` for
  the diagnostic-only CPU rows. `experiment_b_diagnostic.json` and
  `experiment_c_diagnostic.json` are fail-closed scaffolds for the feedback's
  zero-shot and state-reward experiments; they do not authorize formal comparison
  without a frozen model, verified Tier-1 backend, and mechanism-diverse questions.
  `training_log_full.json` includes the analytic flip-loss update diagnostics
  (`loss_before`, `loss_after`, `gradient_norm`, `parameter_update_norm`), while
  `zero_shot_diagnostic.json` is explicitly a no-checkpoint CPU diagnostic and
  therefore keeps `stage_3_zero_shot` closed.
* `tier1_differentiable_suite/` contains the 12-question Tier-1 v0.3 mechanism
  experiment: 48 question-world branch groups (192 action-level rows), 768 exploration-seed observations, eight confirmed
  reversal pairs, shared train/dev/diagnostic_ood data, and genuine small PyTorch
  CPU policy updates for the registered C/D/E method ablations. C is the ordinary
  state-reward sufficiency comparison, D is the branch ablation, and E is the
  confirmed flip-loss ablation plus Evidence-Gated SMOPD teacher distillation. It is not an LLM or formal
  final-OOD result. D also records research regret, erroneous-repair and invalid-local-optimization
  rates, while E records pair-level FlipAcc, unseen-world, noise and nested sample-efficiency
  diagnostics; all remain diagnostic-only and formal final ID/OOD access is closed.
  The suite also records seed-level utility variability explicitly: 7 of 192
  action-level arrays vary across exploration seeds and 185 are constant
  protocol/cost terms, with `formal_seed_variance_claim_authorized=false`.
  These artifacts therefore support CPU mechanism diagnostics, not paper-level
  variance or generalization claims.
* `tier1_v03/` is the independent Tier-1 v0.3 benchmark/calibration snapshot
  (`benchmark_manifest.json`, `summary.json`, `tier1_go.json`, target agreement,
  and seed-level audit rows) used to verify the question/world/seed counts before
  interpreting the C/D/E suite.

The A/B/C/D/E/F files are generated respectively by
`scripts/run_tier1_v03.py`, `scripts/run_tier1_zero_shot.py`, and
`scripts/run_tier1_differentiable_suite.py` (which also writes the explicit F
boundary record). Their JSON artifacts are audit inputs, not visualization-only
reports.

The independent A environment artifact records 192 action-level branch rows and
768 seed observations. This is the same 48 question-world groups used by the C/D/E
dataset; the different counts are a grouping distinction, not a duplicated run.
The F boundary artifact records `fixed_action_mvp_discovery_utility=0` and
`candidate_generation_executed=false`; open-ended discovery is intentionally not
claimed by this fixed-action benchmark.

The real zero-shot B entry point is `scripts/run_tier1_zero_shot.py`. With a user
supplied local frozen checkpoint outside this repository it writes
`tier1_zero_shot.json` and the searchable alias `experiment_b_real_zero_shot.json`.
This workspace contains a genuine local-checkpoint **fresh current-protocol**
diagnostic: all 48 world-level rows were forwarded by the frozen checkpoint. The
stored B artifact and current frozen benchmark both use digest `sha256:542ec9…`;
`freshness_audit.status=fresh_current`, `benchmark_freshness_match=true`, and
`current_full_forward_completed=true`. The runner still fail-closes cached logits
when public observations change. The checkpoint itself is not vendored, so a fresh
checkout without it fail-closes to the available
`pesco_pilot/zero_shot_diagnostic.json` (`pass=false`) instead of fabricating a
result. This B artifact remains diagnostic-only and does not authorize a formal
comparison or open `stage_3_zero_shot`; the current freshness status is recorded in
`artifacts/tier1_zero_shot_current_status.json`.
The frozen model emits the same `A=continue_current_method, S=supported` pair on
all 48 rows; this output collapse is part of the failure diagnosis, not a success
claim.

Recreate them with:

```bash
python -m PESCO.visualization --demo --output PESCO/artifacts/demo_report
python -m PESCO.visualization --tier0 --output PESCO/artifacts/tier0_report
```

For real evaluations, retain the frozen protocol manifest, verifier digest,
source JSON/JSONL, generated `summary.json`, and `report_metadata.json` together. Do not use hidden
labels to build policy prompts; labels in these post-evaluation artifacts are
for audit and visualization only.

The repository-level coverage audit is available at `PESCO/docs/implementation_manifest.json`
and is checked by `python PESCO/scripts/audit_implementation.py`.
